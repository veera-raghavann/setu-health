# PRISM Product Flow

## Entry screen

The patient chooses an intent instead of being forced into a single workflow:

1. Current health concern
2. Health profile
3. Previous medical records
4. ABHA / digital health connectivity

## Current health concern

Voice, touch and text converge into one session:

Input → normalized statement → safety gate → structured missing-information questions → captured history.

## Previous records

File → immutable resource → processing → OCR → source-aware evidence → patient timeline / MedBridge.

## Important product rule

Previous records may enrich case-taking, but they do not replace asking the patient about the current concern.

## Trust model

Every fact should visibly retain whether it is:

- patient reported
- document extracted
- ABHA / exchange sourced
- clinician confirmed
